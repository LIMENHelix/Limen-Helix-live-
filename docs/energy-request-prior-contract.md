# Energy Request-as-Prior Contract

Scope: energy domain only. Status: spec (no code written against it yet). Purpose: define
what it means for an operator request to enter the energy brain as a **top-down prior that
re-enters the existing spine**, versus a **command routed to a handler that bypasses it**.
Any future build is held against the PASS/FAIL test in section 6.

## 0. The one law

> A request may only enter the system as modulation of inputs the existing spine already
> reads. It may never create a new edge from request text to a draft or an effector. If a
> request needs a handler that produces an action outside the perception -> valuation ->
> selection -> gate path, it is a bypass by definition and is rejected.

Rationale: an instruction installs a task set that biases the same loop endogenous goals
use; it does not get its own wire to the effector. A text -> handler -> execute channel is a
frontal-release lesion (utilization behavior) rebuilt on purpose. Draft-and-gate is not a
capital-safety bolt-on; loop-reentry is the only version of "execute" that is an instructed
action rather than a released reflex.

## 1. Three channels (a request is exactly one)

- **QUERY** - read-only readout of existing state. Installs no task set, writes no bias,
  creates no draft, has no side effect. Reads `state.cognition`, `state.diagnoses`,
  `state.opportunities`, `state.energyNeuro`, etc. and formats them. Sits BELOW assist and
  must never be dressed up as a task set.
- **ASSIST** - request writes bias terms at the injection points in section 2. The biased
  spine runs unchanged; the system reports what the biased spine surfaces (including biased
  opportunities). Reaches reporting. Creates NO draft and NO action.
- **EXECUTE** - assist, plus the biased selection is allowed to create a DRAFT that must pass
  the gate (section 3) and then requires human sign-off. No autonomous effector, ever.

## 2. The only permitted injection points (priors into the spine)

A request expresses itself solely as an aggregate `state.requestBiases` object that the named
existing code reads. Biases from multiple requests **compete and decay** (like
`_externalSignals` / `getExternalPressure`), never queue as a FIFO that serializes selection.

| # | Injection point | Existing code that reads it | Bias may do | Bias may NOT do |
|---|---|---|---|---|
| I | Salience / stress bias | `scoreStress` override (same fold-in path as `getExternalPressure`, capped <= 0.3) | add a bounded term to stress | set stress directly |
| II | Condition prior | `deriveDiagnoses` reading `_activeConditions` / a parallel `_requestedConditions` | raise a condition's prior/relevance weight | force `diagnosis.active = true` |
| III | Attention focus | K6 `_computeEnergyAttention` / `_applyNeuroGating` | add topics/diagnoses to the focus set, boost their salience | remove immune/conscience suppressions |
| IV | Valuation weight | `surfaceOpportunities` ranking + `_applyNeuroGating` | tilt ranking (lane/company/urgency preference) | inject a hand-authored opportunity that skips generation |

Selection itself (candidate generation + rank + K2/K6/K7 competition in `surfaceOpportunities`)
is UNCHANGED. Requests bias what competes; they never author the winner.

## 3. The gate every EXECUTE draft must pass (unchanged authorities)

A request-driven draft is created only through the existing `LIMENActionAdapters.createDraft`
path used by `_checkDiagnosisActions`, and only after it clears, in order:

1. **Pulse evidence contract** - `validatedDiagnoses` / `blocked` (a request cannot activate a
   diagnosis the evidence contract blocks).
2. **Immune** - `energyImmune.blockedFromPrompt` / `quarantines` / `immuneState`.
3. **Conscience** - `energyConscience.artifactReadinessDecision` (patent/grant stay vetoed;
   investment/research allowed-with-warning only when source-backed).
4. **Human sign-off** - `approveDraft`. There is no `executeDraft` and none is to be added for
   any real-world / capital action.

## 4. Data shapes

```
Request = {
  id, text, createdAt,
  channel: 'query' | 'assist' | 'execute',
  parse: { method: 'keyword' | 'llm', confidence },   // classifier, upstream of injection
  biases: {                                             // ONLY these four, all optional
    stressBias,                 // number, capped
    conditionPriors: [ {condition, weight} ],
    attentionFocus: [ {id, weight} ],
    valuationWeights: { lane?, company?, urgency? }
  }
}

state.requestBiases = decayed, summed aggregate of active requests' biases (parallel compete)
```

A request is stored as a **prior/task-set object, not an imperative command**, so the
selection function it biases can later be generated by the system itself. This is the property
that lets routine action-selection eventually transfer off the operator; consequential
sign-off stays with the human permanently.

## 5. Classifier property

Text -> `biases` is the only job of the parser (keyword or LLM). It never executes. A bad or
off-vocabulary parse must degrade gracefully: weak or empty `biases`, so the spine behaves as
if no request arrived. The classifier is more isomorphic as an LLM (graded semantic mapping)
than as keyword S-R; the token-cost tradeoff against the freeze is the operator's to weigh and
is orthogonal to this contract.

## 6. PASS / FAIL test for any diff

**PASS** if the change only:
- adds/reads bias terms at injection points I-IV, and
- routes any action through the section 3 gate, and
- keeps QUERY side-effect-free.

**FAIL** (bypass) if the change introduces any of these edges:
- request text -> `createDraft` that skips pulse/immune/conscience,
- request text -> any effector (fetch POST, email, order, publish, deploy) directly,
- request text -> `diagnosis.active = true` (skips evidence contract),
- request text -> `state.stress =` direct set (skips perception),
- request text -> direct mutation of `state.opportunities` / `state.treatments`,
- a request queue that preempts or serializes selection,
- output presented to the operator as "executed/done" rather than "assisted" or
  "drafted, pending sign-off".

## 7. Carried caveats (must be honored by any build)

- **Anosognosia stamp.** QUERY and ASSIST read from the self-model, which can score itself
  healthy on structural markers, over a still single-channel interoceptive layer. Every
  request output must carry its honesty state (immune state, confidence, and the
  interoception-is-single-channel caveat). Delivery does not fix this; it surfaces it. The fix
  is multimodal interoception, still unbuilt.
- **No new serial bottleneck.** Requests are competing biases with decay, not tickets.
- **No homunculus hardening.** The console must advance the transfer-of-selection goal (request
  as a self-generable prior), not entrench the operator as the permanent action-selector for
  routine valuation.

## 8. Out of scope for this contract

Persistence of `requestBiases` across reloads, headless execution, and the classifier backend
are substrate concerns gated by the freeze; they do not change this contract, they only decide
where it runs.
